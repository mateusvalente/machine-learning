MACHINE LEARNING · MODELOS DE IA

Cada modelo existe para enxergar um tipo de padrão.

Não procuramos o modelo mais sofisticado, mas aquele cuja estrutura combina com o problema, os dados e a forma como a resposta será utilizada.

01 · POR QUE EXISTEM TANTOS MODELOS?

Porque “aprender” não é uma única tarefa.

Uma linha é ótima para representar uma tendência simples, mas não reconhece diretamente uma forma dentro de uma imagem. Uma árvore descobre regras em tabelas, mas não aproveita a posição espacial de pixels como uma CNN. Um Transformer relaciona elementos distantes de uma sequência, porém custa mais do que uma regressão. Cada arquitetura introduz uma forma preferencial de representar padrões.

NecessidadePor que pede outro modelo?Exemplo
Prever um númeroA saída precisa variar continuamente.Preço, consumo ou demanda.
Escolher uma classeO modelo precisa construir uma fronteira ou probabilidades entre categorias.Fraude, spam ou diagnóstico.
Descobrir gruposNão existem rótulos corretos; é preciso procurar estrutura nos próprios dados.Segmentos de clientes.
Entender posiçãoA vizinhança espacial contém informação importante.Objetos em imagens.
Entender sequênciaA ordem e o contexto alteram o significado.Texto, fala ou série temporal.
Gerar conteúdoO objetivo não é apenas escolher uma resposta, mas produzir uma nova amostra.Texto, imagem ou áudio.

02 · MODELOS CLÁSSICOS

Começar simples ajuda a entender o problema.

Esses modelos costumam ser rápidos, fortes em dados tabulares e úteis como linha de base. Muitos também permitem explicar como as características influenciam a resposta.

Regressão Linear

Regressão · supervisionada

Representa a saída como uma soma ponderada das entradas. Existe para estimar relações aproximadamente lineares e quantificar o efeito de cada variável.

É boa para
Previsões numéricas simples, tendências e modelos de referência interpretáveis.
Problemas
Preço de imóvel, vendas, demanda e consumo.
Limite principal
Não representa curvas e interações complexas sem criar novas características.
Ver laboratório de Regressão Linear →

Regressão Logística

Classificação · supervisionada

Aplica uma função logística à combinação linear para estimar uma probabilidade. Existe para transformar um escore linear em uma decisão de classificação interpretável.

É boa para
Classificação binária, probabilidades e comparação do efeito das variáveis.
Problemas
Churn, aprovação de crédito, conversão e risco.
Limite principal
Sem engenharia de atributos, sua fronteira continua linear.

Perceptron

Classificação linear · supervisionada

Combina entradas, pesos e bias e aplica um degrau. Existe como uma regra simples para aprender uma fronteira linear a partir de erros de classificação.

É bom para
Ensinar o neurônio artificial e separar classes linearmente separáveis.
Problemas
Decisões binárias simples e portas AND/OR.
Limite principal
Um único Perceptron não resolve XOR nem produz probabilidades.
Estudar o Perceptron →

ADALINE

Classificação linear · supervisionada

Ajusta os pesos usando o erro da saída linear antes do degrau. Existe para substituir a correção binária do Perceptron por uma superfície de erro contínua e derivável.

É boa para
Entender Regra Delta, LMS e descida do gradiente.
Problemas
Classificação linear e adaptação de sinais simples.
Limite principal
Continua limitada a uma fronteira linear.
Estudar a ADALINE →

MADALINE

Classificação · múltiplas ADALINEs

Combina diversas unidades ADALINE em uma pequena rede. Existe para produzir decisões mais complexas do que uma única unidade linear consegue representar.

É boa para
Visualizar como várias fronteiras lineares formam uma região não linear.
Problemas
XOR e classificações binárias com regiões compostas.
Limite principal
Regras clássicas de treinamento são mais específicas que o backpropagation moderno.
Estudar a MADALINE →

Árvore de Decisão

Classificação ou regressão · supervisionada

Divide os dados com perguntas sucessivas do tipo “valor ≤ limite?”. Existe para aprender regras, interações e relações não lineares sem exigir uma fórmula linear global.

É boa para
Dados tabulares, regras explicáveis e relações com limites claros.
Problemas
Crédito, triagem, risco, preço e decisão operacional.
Limite principal
Uma árvore profunda pode decorar o treino e variar muito com pequenas mudanças.

Random Forest

Classificação ou regressão · ensemble

Combina várias árvores treinadas com amostras e características aleatórias. Existe para reduzir a instabilidade de uma árvore isolada por votação ou média.

É boa para
Dados tabulares, bom desempenho inicial e pouca preparação de escala.
Problemas
Fraude, risco, propensão, qualidade e previsão de valores.
Limite principal
É menos explicável e maior do que uma única árvore.

Gradient Boosting

Classificação ou regressão · ensemble

Cria árvores em sequência, cada uma corrigindo o erro residual do conjunto anterior. Existe para transformar vários modelos fracos em um preditor tabular muito preciso.

É bom para
Tabelas estruturadas com relações não lineares e interações complexas.
Problemas
Risco financeiro, ranking, churn e previsão de demanda.
Limite principal
Exige ajuste cuidadoso e pode sobreajustar ou aprender vieses dos dados.

SVM e SVR

Classificação ou regressão · supervisionada

A SVM procura uma fronteira com margem ampla; kernels permitem fronteiras curvas. A SVR adapta a ideia para valores contínuos. Elas existem para controlar a complexidade por margem e vetores de suporte.

São boas para
Conjuntos pequenos ou médios, muitas características e fronteiras bem definidas.
Problemas
Texto, bioinformática, caracteres, classificação e regressão.
Limite principal
Escala importa; kernels podem ficar caros em datasets muito grandes.
Estudar SVM e margem máxima →

k-NN

Classificação ou regressão · vizinhança

Consulta os exemplos mais próximos e responde por votação ou média. Existe porque pontos parecidos frequentemente possuem respostas parecidas, sem precisar ajustar uma fórmula global.

É bom para
Datasets menores, padrões locais e uma linha de base intuitiva.
Problemas
Recomendação por similaridade, reconhecimento simples e interpolação.
Limite principal
Predição fica cara, a escala altera distâncias e muitas dimensões reduzem a noção de proximidade.

LVQ

Classificação · protótipos supervisionados

Aprende poucos protótipos rotulados e classifica pela proximidade. Existe para representar as classes de forma compacta, em vez de guardar todos os exemplos como o k-NN.

É bom para
Classificação rápida e protótipos que podem ser inspecionados.
Problemas
Padrões de áudio, imagens e dados rotulados vetoriais.
Limite principal
Inicialização, escala e quantidade de protótipos afetam bastante o resultado.
Estudar LVQ →

k-means

Agrupamento · não supervisionado

Move k centroides para minimizar a distância dos dados ao centro do grupo atribuído. Existe para descobrir agrupamentos quando não há rótulos disponíveis.

É bom para
Segmentação exploratória e grupos aproximadamente compactos e esféricos.
Problemas
Perfis de clientes, compressão de cores e resumo de dados.
Limite principal
É preciso escolher k; escala, outliers e grupos de formas irregulares causam problemas.

03 · REDES NEURAIS

Arquiteturas diferentes preservam estruturas diferentes.

Redes neurais aprendem representações em camadas. O tipo de conexão define se a rede trata uma tabela, uma imagem, uma sequência ou regiões locais do espaço.

MLP

Classificação ou regressão · feedforward

Conecta camadas densas e usa ativações não lineares. Existe para combinar várias fronteiras e aproximar relações que um neurônio linear não resolve.

É boa para
Vetores e tabelas numéricas com relações não lineares.
Problemas
XOR, classificação, regressão e aproximação de funções.
Limite principal
Não incorpora naturalmente posição espacial ou ordem temporal.
Estudar MLP e backpropagation →

RBF

Classificação ou regressão · bases radiais

Ativa neurônios pela distância entre a entrada e centros aprendidos. Existe para representar respostas locais: cada unidade cuida de uma região do espaço.

É boa para
Interpolação, aproximações suaves e fronteiras formadas por regiões.
Problemas
Controle de sistemas, séries, classificação e regressão não linear.
Limite principal
Centros, largura Gaussiana e escala precisam ser bem definidos.
Estudar a rede RBF →

CNN

Visão e sinais · convolucional

Aplica filtros compartilhados em pequenas regiões. Existe para aproveitar a estrutura espacial e reconhecer o mesmo padrão em posições diferentes sem criar um peso para cada conexão possível.

É boa para
Formas, texturas, bordas e padrões locais.
Problemas
Classificação, detecção e segmentação de imagens; áudio e sinais.
Limite principal
Treino pode exigir muitos dados e processamento; contexto global pede camadas ou mecanismos adicionais.
Estudar CNN →

RNN, LSTM e GRU

Sequências · recorrentes

Carregam um estado ao percorrer a sequência. LSTM e GRU controlam o que lembrar e esquecer. Existem para modelar ordem e dependência temporal com memória interna.

São boas para
Séries temporais e sequências processadas passo a passo.
Problemas
Previsão temporal, fala, texto e sensores.
Limite principal
Processamento sequencial dificulta paralelização e dependências muito longas.

Transformer

Sequências e multimodal · atenção

Usa autoatenção para relacionar elementos da entrada diretamente. Existe para capturar contexto distante e processar posições em paralelo, reduzindo a dependência da recorrência.

É bom para
Linguagem, contexto longo, múltiplas modalidades e aprendizado em grande escala.
Problemas
Tradução, geração de texto, código, visão, áudio e proteínas.
Limite principal
Treino e inferência podem consumir muita memória, dados e energia.
Estudar Transformers →

Autoencoder

Representação · reconstrução

Comprime a entrada em uma representação latente e tenta reconstruí-la. Existe para aprender características úteis sem precisar de um rótulo para cada exemplo.

É bom para
Redução de dimensionalidade, remoção de ruído e representação.
Problemas
Compressão, detecção de anomalias e pré-treinamento.
Limite principal
Reconstruir bem não garante que a representação seja ideal para a tarefa final.

04 · MODELOS GENERATIVOS

Prever uma resposta e criar uma amostra são objetivos diferentes.

Modelos generativos procuram representar como os dados poderiam ser produzidos. Eles podem gerar, completar, reconstruir ou transformar conteúdo.

GAN

Geração · jogo adversário

Coloca um Gerador contra um Discriminador: um produz amostras e o outro tenta detectar as falsas. Existe para aprender a gerar exemplos realistas sem definir manualmente todas as características visuais.

É boa para
Imagens visualmente nítidas, tradução entre domínios e aumento de resolução.
Problemas
Geração de rostos, estilos, imagens sintéticas e super-resolução.
Limite principal
Treinamento instável e risco de produzir pouca variedade.
Estudar GANs →

Modelo de Difusão

Geração · remoção de ruído

Aprende a reverter gradualmente um processo que adiciona ruído aos dados. Existe para transformar ruído em amostras coerentes por uma sequência estável de refinamentos.

É bom para
Geração e edição de imagens com diversidade e controle por condições.
Problemas
Texto para imagem, preenchimento, áudio e vídeo.
Limite principal
Normalmente requer várias etapas de inferência e bastante computação.

LLM

Linguagem · modelo autorregressivo

Um Grande Modelo de Linguagem normalmente usa Transformer e aprende a prever tokens a partir do contexto. Existe para reutilizar o aprendizado estatístico da linguagem em muitas tarefas, em vez de treinar um modelo separado para cada uma.

É bom para
Geração, resumo, tradução, perguntas, código e interfaces em linguagem natural.
Problemas
Tarefas textuais gerais e sistemas multimodais quando adaptado.
Limite principal
Pode produzir informação incorreta, refletir vieses e exigir validação e controle externos.

05 · UMA DISTINÇÃO IMPORTANTE

Discriminativo não significa “simples”; generativo não significa “melhor”.

A diferença está no objetivo aprendido. Um modelo discriminativo foca a resposta necessária para uma entrada. Um modelo generativo aprende regularidades suficientes para produzir ou completar dados.

Preditivo ou discriminativo

Recebe x e estima diretamente uma classe ou um valor.

transação → fraude / legítima
≠

Generativo

Recebe contexto ou ruído e constrói uma nova amostra.

descrição → imagem nova

06 · GUIA DE PARTIDA

Que modelo experimentar primeiro?

Esta tabela sugere pontos de partida, não vencedores automáticos. O resultado precisa ser confirmado em validação e teste.

ProblemaPrimeiro modeloQuando avançar
Valor contínuo e relação simplesRegressão LinearUse árvores, boosting, SVR ou MLP quando resíduos mostrarem relações não lineares.
Classificação binária explicávelRegressão Logística ou ÁrvoreCompare Random Forest, boosting e SVM quando precisar de fronteiras mais complexas.
Tabela estruturadaRegressão/Árvore como baselineRandom Forest e Gradient Boosting costumam ser comparações fortes.
Poucos dados e muitas característicasModelo linear regularizado ou SVMTeste kernels e ajuste C apenas com validação.
Similaridade localk-NNUse LVQ se precisar resumir os exemplos em protótipos.
Grupos sem rótulok-meansEscolha outros métodos se os grupos não forem compactos ou tiverem muito ruído.
ImagemCNNTransformers visuais e modelos pré-treinados ajudam em escala e contexto global.
Sequência ou textoRNN para estudo; Transformer para contexto e escalaUse modelo pré-treinado quando dados e computação próprios forem limitados.
Gerar imagensDifusão ou modelo pré-treinadoGAN pode ser útil quando nitidez e inferência rápida são centrais.

Regra prática: construa primeiro uma linha de base pequena e compreensível. Só aumente a complexidade quando os erros mostrarem uma limitação real, e não apenas porque uma arquitetura é mais recente.

TRILHA DE ESTUDO

Escolha o modelo pelo padrão que precisa aprender.

Antes de comparar arquiteturas, defina a tarefa, prepare os dados e escolha uma métrica que represente o uso real.

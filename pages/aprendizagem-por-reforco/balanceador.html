1 · QUAL ALGORITMO E QUAIS PARÂMETROS SÃO USADOS?

Especificação técnica do Agente e da Infraestrutura

O balanceador não conhece antecipadamente a capacidade de CPU de cada contêiner; ele descobre a topologia unicamente pela latência HTTP medida.

ALGORITMO E MDP

Q-Learning Tabular Off-Policy

  • Estados (S): carga_baixa, carga_media e carga_alta (representando o volume atual de tráfego na rede).
  • Ações (A): Roteamento HTTP via Nginx para node1, node2 ou node3.
  • Estrutura: Dicionário Python puro Q_TABLE[estado][acao] (matriz 3×3 inicializada em 0.0).
  • Política: ε-greedy (explora rotas aleatórias com probabilidade ε e escolhe arg max Q(s,a) com probabilidade 1 − ε).
HIPERPARÂMETROS

Parâmetros da Equação de Bellman

  • Taxa de Aprendizado (α = 0.25): Atualiza 25% da estimativa a cada requisição HTTP para absorver variações de rede (jitter) sem oscilar brusca ou erradamente.
  • Fator de Desconto (γ = 0.85): Pondera a estabilidade futura do próximo estado da rede max Q(s', a').
  • Exploração Inicial (ε = 0.40 → 0.05): Começa testando todos os servidores em 40% das chamadas e decai por 0.992 a cada episódio até estabilizar em 5%.
  • Timeout HTTP: 500ms (0.50s na biblioteca requests).
FUNÇÃO DE RECOMPENSA (R)

Conversão de Latência em Pontos

  • Latência < 100ms: R = +20.0 (Pontuação máxima — SLA de alta velocidade cumprido).
  • 100ms ≤ Latência < 250ms: R = +2.0 (Resposta aceitável, mas com contenção de CPU).
  • 250ms ≤ Latência ≤ 500ms: R = −15.0 (Penalidade por lentidão perceptível).
  • Timeout (> 500ms) ou Erro 5xx: R = −100.0 (Punição severa para afastar imediatamente o tráfego do nó saturado).

PASSO A PASSO · DECISÃO vs. BELLMAN

A exata mesma lógica do Tamagotchi aplicada nos servidores!

Aqui não temos Fome × Energia, mas sim uma matriz de 3 Estados de Carga × 3 Servidores (9 notas na memória):

1. ANTES de enviar a requisição (Decisão ε-Greedy): O Python olha apenas a linha do estado atual da rede e vê as 3 notas salvas (node1, node2, node3). Começa com 30%–40% de chute aleatório (ε) e vai caindo a cada requisição até escolher quase sempre a maior nota! 2. DEPOIS que a resposta HTTP volta (Equação de Bellman): Medimos os milissegundos da resposta, transformamos em pontos (+20 se <100ms ou −100 se deu Timeout) e atualizamos apenas a nota daquele servidor que acabamos de testar!

agente.pyTreinamento de 500 episódios em Python puro + requests
import json
import random
import time
import requests

NGINX_BASE_URL = "http://localhost:8080"
REQUEST_TIMEOUT_SEC = 0.50  # 500ms

# Espaço de Estados (S) e Espaço de Ações (A)
STATES = ["carga_baixa", "carga_media", "carga_alta"]
ACTIONS = ["node1", "node2", "node3"]

# Hiperparâmetros da Equação de Bellman
ALPHA = 0.25          # Taxa de aprendizado (Learning Rate)
GAMMA = 0.85          # Fator de desconto futuro (Discount Factor)
EPSILON_START = 0.40  # Taxa inicial de exploração (Epsilon-Greedy)
EPSILON_MIN = 0.05    # Exploração mínima residual
EPSILON_DECAY = 0.992 # Decaimento por episódio
EPISODES = 500        # Total de episódios de treinamento

# Q-Table inicializada com zeros usando apenas dicionários nativos
Q_TABLE = {state: {action: 0.0 for action in ACTIONS} for state in STATES}

def select_action(state: str, epsilon: float) -> tuple[str, str]:
    if random.random() < epsilon:
        return random.choice(ACTIONS), "EXPLORACAO"
    q_values = Q_TABLE[state]
    max_q = max(q_values.values())
    best_actions = [act for act, val in q_values.items() if val == max_q]
    return random.choice(best_actions), "EXPLOTACAO"

def calculate_reward(latency_ms: float, timed_out: bool) -> float:
    if timed_out:
        return -100.0  # Punição severa por Timeout (> 500ms)
    if latency_ms < 100.0:
        return +20.0   # Pontuação máxima para respostas rápidas (< 100ms)
    if latency_ms < 250.0:
        return +2.0    # Recompensa baixa para latência moderada
    return -15.0       # Penalidade por lentidão

def update_q_table(state: str, action: str, reward: float, next_state: str) -> float:
    # EQUAÇÃO DE BELLMAN: Q(s,a) <- Q(s,a) + alpha * [ R + gamma * max Q(s',a') - Q(s,a) ]
    current_q = Q_TABLE[state][action]
    max_future_q = max(Q_TABLE[next_state].values())

    td_target = reward + (GAMMA * max_future_q)
    td_error = td_target - current_q

    new_q = current_q + (ALPHA * td_error)
    Q_TABLE[state][action] = new_q
    return new_q
